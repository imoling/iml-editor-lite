# 手写图层旁挂文件格式（iPad ↔ Mac 共用）

> 版本：0.1（2026-09-13）　·　状态：草案，iPad 端 v0 按此实现，Mac 端只读显示待做

## 1. 原则

- **正文永远是纯 Markdown**：`笔记.md` 是唯一的内容真源，任何编辑器都能打开。
- **手写是旁挂图层，不是文档的一部分**：与正文同名、同目录，靠文件名关联；删掉旁挂文件，笔记本身不受影响。
- **同步靠文件系统**：iCloud Drive、WebDAV、同步盘都是文件级同步，格式设计只保证"每个文件独立可替换"。

## 2. 文件

以 `会议记录.md` 为例，同目录下：

| 文件 | 内容 | 谁写 | 谁读 |
|---|---|---|---|
| `会议记录.md` | Markdown 正文 | Mac / iPad | 所有端 |
| `会议记录.ink` | PencilKit `PKDrawing.dataRepresentation()` 二进制（Apple 格式，PencilKit 自带版本兼容） | iPad | iPad（可编辑）、Mac（暂不解析） |
| `会议记录.ink.png` | 手写图层的位图快照，透明背景，2× 分辨率 | iPad（每次保存笔迹时重新导出） | Mac 只读叠加显示、非 Apple 平台 |

后续可增加 `会议记录.ink.svg`（矢量快照），PencilKit 没有原生 SVG 导出，需要自行把 `PKStroke` 路径转成 SVG path，放到 v1。

Mac 端笔记库树只显示 `.md / .markdown / .txt`，所以 `.ink` 与 `.ink.png` 不会出现在侧边栏里，但会跟着文件夹一起同步。

## 3. 坐标系（v0：页面级覆盖）

- 画布宽度固定 **820 pt**，与 iPad 端正文视图等宽；高度随正文内容增长，最小为屏幕高度。
- 原点在正文视图左上角，y 向下；`PKDrawing.bounds` 使用同一坐标系。
- `.ink.png` 按 `PKDrawing.bounds` 外扩 8 pt 裁切导出，并在 PNG 旁写入位置信息：Mac 端显示时按 820 pt 宽度等比缩放，叠在正文渲染结果之上。位置信息写在 `会议记录.ink.json`：

```json
{ "version": 1, "canvasWidth": 820, "bounds": { "x": 12.5, "y": 340.0, "width": 400.0, "height": 160.0 } }
```

v0 的局限：正文在 Mac 端和 iPad 端的排版不完全一致，页面级坐标只能做到"大致对齐"。这是可接受的起点——GoodNotes 的手写也是页面级的。

## 4. 锚定（v1：段落级）

把手写笔画按所属段落分组，每组记录"段落 id + 相对该段落顶部的偏移"，正文插入或删除段落时笔迹跟着段落移动。段落 id 取正文中的稳定标识（标题文本哈希 / 段落首 20 字哈希），失配时回退到页面级坐标。这一步依赖 Mac 端与 iPad 端使用同一套 Markdown 分段规则，放到 iPad v1。

## 5. 保存与冲突

- 笔迹为空时删除 `.ink` 与 `.ink.png`，避免留下空文件。
- 所有写入走 `NSFileCoordinator`（iPad）/ 原子写（Mac），防止同步盘读到半个文件。
- 冲突规则：
  - 正文 `.md`：iCloud 产生的冲突版本由系统提供（`NSFileVersion`），iPad 端 v0 先"保留双方、提示用户"；Mac 端已实现"磁盘被外部修改时橙点提示，保存即覆盖"。
  - 笔迹 `.ink`：以修改时间新者为准，旧版本另存为 `会议记录 (冲突 2026-09-13 21-30).ink`。

## 6. 路线

1. iPad v0（`ipad/iMLNotes.swiftpm`）：选择笔记库文件夹（推荐 iCloud Drive/iML Notes）、浏览、编辑正文、手写覆盖层、按本规范保存。
2. Mac：阅读模式叠加显示 `.ink.png`，可切换显隐。
3. iPad v1：段落级锚定、SVG 导出、冲突处理界面。
