对标 Obsidian：功能差距分析与补齐建议

2026-09-20 · 基于 iML Markdown Editor v26.3.1 当前代码 · Obsidian 一侧的数据于同日联网抓取，口径与局限见文末

一句话结论：Obsidian 的口碑立在三样东西上——本地纯文本、链接、插件生态。前两样我们已有大半；第三样我们决定不做，对策是「把最常装的插件内置」。对照官方下载榜 Top 30，我们已内置其中 8 个、部分覆盖 6 个。

最该补的有两类：一是链接的最后几针（[[笔记#小节]] 跳转、![[嵌入]] 渲染、未链接提及、别名、悬浮预览）——都是 1~5 天的活，补完后从 Obsidian 搬来的库才算真能用；二是下载榜上证据最硬、我们又正好差一层皮的：日历（312 万）、全库待办（Tasks 428 万）、标签改名（Tag Wrangler 110 万）、快速捕获（QuickAdd 213 万）。

别丢的优势：Obsidian 官方明确不内置 AI，用户要装 Copilot + Smart Connections + Ollama 自己拼；而连反对 AI 进笔记库的人都认可的三种用法——相似度搜索、相关笔记、语音转文字——正好是我们已经内置的三样。

被抱怨最多的地方 = 我们的机会

  • 上手门槛高、开局一片空白——Product Hunt 批评关键词第一
  • 折腾插件——「整个下午都在调查询和过滤器」；插件弃置、更新搞坏库、互相冲突
  • 同步要么付费要么折腾——官方 4~8 美元 / 月且需外币支付
  • 移动端慢——评分最低，约 30% 插件不兼容
  • 搜索不按相关性排序、无语义 / 模糊匹配（官方路线图上还挂着）
  • 国内网络——插件市场在 GitHub 上，常打不开
  • 迁出去思源的四条理由：开箱即用、所见即所得、中文排版、不依赖插件

#功能判断量级
17局部关系图谱建议做，只做局部。调研印证了分工：全局图谱「一堆点，什么也做不了」，多名用户直接关掉；但「图谱」又是 Product Hunt 好评关键词（16 次）——它负责拉新，不负责留存。所以按「脸面」来做：当前笔记周围 1~2 跳，并且画出别人没有的「语义相近」边（相关笔记的数据现成）M
18并排窗格要拆掉「只有一个活动编辑器」的假设，牵动 store 和快捷键。建议先做轻量版：右侧并排一个只读预览窗格M / L
19WebDAV 同步这是我的建议和调研排序分歧最大的一项，请你定。调研里同步排第 3、是中文用户头号痛点，也和你「支持 iCloud 以外云盘」的设想一致。我仍建议排后：Obsidian 的同步之痛主要发生在手机上，而我们目前只有桌面端——电脑之间用同步盘目录（#11）已经够用；同步引擎是「做不好就丢数据」的功能，值得等 iPad 端有实质进展时一起设计L
20手绘图块下载量第一的需求（808 万），而官方 Canvas 多年不支持手绘（509 赞）。Excalidraw 本身是开源的 React 组件，理论上可以作为一种图块嵌进来，导出的 SVG 里自带可再编辑的数据——Markdown 里仍是一个普通图片链接，符合我们的保真原则，也和 iPad 手写的方向一致。但我还没评估过接入成本（包体积、懒加载、与现有图片管线的配合），先列为待评估L？
21网页剪藏官方 Web Clipper 被评为「现存最好的网页剪藏」。分两步：先做应用内的「粘贴网址 → 抓正文转成笔记」，够用就不做浏览器扩展——扩展要上架、要维护，是另一条产品线M → L
22给 agent 留个门增长最快的用法：Claudian 2026 年才起来就到第 12 名，官方也在 2026-02 出了 CLI。我们的库是普通文件夹，Claude Code 今天就能直接用——零成本的第一步是在 README 写清楚这一点。再进一步可以出一个只读的 MCP 服务，把我们已有的语义检索暴露出去（这是纯文件夹给不了 agent 的）文档 → M
23属性视图（轻量 Bases）长期看这是最大的真缺口（Dataview 500 万、Bases 4.4 分），但属于重度用户。不做查询语言——用户正是因为不想写代码才从 Dataview 迁去 Bases。只做「按属性 / 标签筛出的笔记列表，可切表格」。依赖 #12L
24块引用 ^id重度用户才用。先保证「原文保真、点了能跳过去」，补全到块缓做M / L

搜索：调研改变了我原来的建议

我原本想建议加 tag: path: 过滤语法和正则。但调研显示用户要的不是这个：Omnisearch 的 190 万下载和官方路线图指向的都是「按相关性排序、能容错、能语义匹配」——这些我们已经有大半（标题加权 + 语义补充结果）。所以过滤语法降为可有可无的小项。

六、建议不做的

功能为什么不做
插件系统9 月 19 日已定。调研补了一条理由：插件是 Obsidian 的头号好评，也是头号抱怨（弃置、冲突、更新搞坏库），2026 年还出过借共享库投放木马的安全事件
Canvas 白板XL 级投入；官方自己做了也只拿到 3.5 分、功能停滞。真实需求是「手绘」，由 #20 去接
全局图谱好看没用，只做局部
查询语言（Dataview 式）用户正在逃离它。自然语言问笔记更适合我们
格式规整（Linter 式）和「不动用户没碰过的原文」的保真原则相反
Publish、幻灯片、文件夹图标、主题市场离「记笔记」太远，或纯装饰。Publish 官方评分也只有 3.7

七、别丢的优势

Obsidian CEO 的立场是「不要把理解外包给 AI」，核心里不做任何通用 AI 助手，只给外部 agent 留接口。这给「想要开箱即用、内置、能接本机模型的轻量 AI」的用户留出了一个明确的空位。

我们有的Obsidian 用户要怎么才能有
本机实时转写 + 区分说话人 + 点句回听 + 打点基本拼不出来。「会议转写和摘要」在调研里是常见的 AI 使用场景，但只能靠外接服务，没有时间轴联动
「问你的笔记」（强制标出处、识别拒答）Copilot（199 万）+ 自配嵌入模型 + 自配对话模型
语义搜索 / 相关笔记Smart Connections（121 万）
应用自己托管本机模型自己装 Ollama，再到每个插件里填地址。调研里用户对本地 AI 的三大抱怨——配置复杂、分块行为不透明、质量不如云端——前两条正是我们解决的
AI 请求去向常驻可见没有对应物，各插件各管各的
所见即所得，且保存逐字保真「完全所见即所得」是 792 赞的老请求；迁去思源的人列的第二条理由就是它
直接打开任意 .md 文件552 赞的老请求，1.14（2026-09 内测）才支持
每次保存的版本历史 + diff核心的 File recovery 只按时间间隔留快照；要 diff 得上 Git 插件（317 万）
图片自动压缩 + 孤儿清理240 赞的请求，1.12 才部分解决

一条值得写进产品原则的反对意见：《Keep AI Out of Your Vault》认为 AI 摘要会稀释个人知识库、自动链接和自动整理不可取；作者能接受的用法只有三种——相似度搜索、找相关笔记、语音转文字。这三样正好是我们已经做的。路线图里的「AI 建议标签 / 归档」坚持「只建议、用户确认」是对的，未链接提及的语义版（#3）也应如此。
