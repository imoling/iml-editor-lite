## 26.4.2 — 拖进来就打开，双链能点，图片能写进文档

这一版做的三件事都来自 Issues 里的反馈（[#1](https://github.com/imoling/iml-editor-lite/issues/1)、[#2](https://github.com/imoling/iml-editor-lite/issues/2)、[#3](https://github.com/imoling/iml-editor-lite/issues/3)），谢谢三位。

### 把文件拖进窗口就打开

把 `.md`、`.txt` 或者一个文件夹拖到窗口的任意位置：文档开成标签页，文件夹开到侧边栏。之前拖进来光标显示「复制」，松手却什么都不发生。

图片照旧拖到正文里插入。源码模式下拖进来的文本文件，不会再被当成一段文字插进正文。

### 双向链接能点了

点一下 `[[笔记]]`，打开同名的文档；`[[笔记#小节]]` 打开后跳到那一节，`[[#小节]]` 在本篇里跳。没有这篇文档时，状态栏会问要不要新建。富文本模式和源码模式的预览里都能点；按住 `⌘`（Windows 上是 `Ctrl`）再点是选中它，方便删改。

找的范围是当前文档所在的文件夹，加上侧边栏打开的文件夹，按文件名认。点的时候现找，不建索引——轻量版「不在背后做事」这一条没变。

反向链接、输入 `[[` 时的补全、按标题和别名链接，仍然只有完整版 [iML Markdown Editor](https://github.com/imoling/iml-markdown-editor) 有。

### 图片可以写进文档里

设置 → 粘贴与输入 → 图片存放位置，选「文档里」。之后粘贴、拖入的图片会先压缩，再直接写进文档：整篇只有一个文件，换电脑、发给别人都不用带着 `assets/` 文件夹。还没保存过的文档也能插图了。

代价是文件会比图片本身大三分之一左右，所以默认仍然是存在文档旁的文件夹里。

源码模式下，写进文档的图片是很长的一串字符，现在会折成一个小标签（如 `… 396 KB …`）。只是显示上折起来，文件内容不变；从别处拿来的、带内嵌图片的文档也一样。

### 下载

| 平台 | 安装包 |
|---|---|
| macOS Apple Silicon（M 系列） | `iML-Editor-Lite-26.4.2-arm64.dmg` |
| macOS Intel | `iML-Editor-Lite-26.4.2-x64.dmg` |
| Windows（绝大多数电脑选这个） | `iML-Editor-Lite-Setup-26.4.2-x64.exe` |
| Windows on ARM（骁龙本等） | `iML-Editor-Lite-Setup-26.4.2-arm64.exe` |

没有做 Apple 公证。macOS 首次打开若被拦下：系统设置 → 隐私与安全性 → 拉到底点「仍要打开」。Windows 需要 WebView2（Windows 11 自带；Windows 10 没有的话安装程序会帮你装）。
